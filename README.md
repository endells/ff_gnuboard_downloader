# 그누보드 TXT 다운로더 · FF 플러그인 v0.1.3

그누보드 게시판의 게시글을 한 폴더에 제목별 TXT로 저장하고, 같은 작품이 설정한 편수 이상 모이면 작품 폴더로 복사합니다. EPUB·이미지 다운로드는 만들지 않습니다.

## 설치

대상 환경은 **Linux 기반 FlaskFarm, Python 3.8 이상**입니다.

1. FF의 **시스템 → 플러그인 관리 → 플러그인 설치**에서 아래 주소를 입력합니다.
2. 주소 뒤에 `.git`이나 마지막 `/`를 붙이지 않습니다.
3. 설치가 끝나면 FF를 재시작합니다.
4. 메뉴의 **그누보드 TXT 다운로더 → 설정 / 스케줄**을 엽니다.

```text
https://github.com/endells/ff_gnuboard_downloader
```

이후에는 FF의 플러그인 업데이트를 활성화하고 FF를 재시작하면 새 코드가 적용됩니다. 다운로드한 TXT와 FF 데이터 폴더의 설정·이력은 보존합니다.

### 목록에 제목 없이 패키지명과 null만 나올 때

FF는 플러그인 폴더를 찾았지만 `setup.py` 초기화를 완료하지 못했을 때 이 형태로 표시할 수 있습니다. `null`은 설명이 아니라 FF의 로딩 상태 표시입니다. 이 화면만으로 실제 오류 원인을 알 수는 없습니다.

1. FF를 재시작하세요. 기본 설정에서는 시작할 때 Git 플러그인이 업데이트됩니다. 자동 업데이트를 꺼 놓았다면 시스템 설정의 `config.yaml`에서 `plugin_update: true`를 확인하세요. `UPDATE_STOP=true` 또는 `PLUGIN_UPDATE_FROM_PYTHON=false` 환경변수로 업데이트가 차단된 경우에는 아래 수동 갱신 명령을 사용하세요.
2. 정상 반영되면 목록에 **그누보드 TXT 다운로더 / endells / 0.1.3**이 나타납니다.
3. 플러그인 메뉴를 열어 **플러그인 로딩 완료** 또는 **파일 설치 완료 · 실행 준비 실패** 상태를 확인하세요. 실패 화면에는 오류와 해결 방법이 표시됩니다.
4. 여전히 제목이 비어 있으면 FF 시스템 시작 로그에서 `ff_gnuboard_downloader` 또는 `NOT normal plugin` 앞뒤의 Traceback을 확인하세요.

자동 업데이트가 꺼져 있거나 동작하지 않으면 FF 컨테이너 콘솔에서 설치 폴더를 지정해 갱신할 수 있습니다. 다음은 FF 데이터 경로가 `/data`인 예시입니다. 실제 경로에 맞춰 실행하고 FF를 재시작하세요.

```bash
git -C /data/plugins/ff_gnuboard_downloader pull --ff-only
```

업데이트를 위해 플러그인을 삭제하거나 DB·TXT를 지울 필요는 없습니다.

### 0.1.3 변경 사항

- FF에 `bs4`와 `soupsieve`가 모두 없어도 실행되도록 파서 wheel을 동봉했습니다. 별도 pip 설치나 시작 시 패키지 다운로드가 필요하지 않습니다.
- 기존 FF에 설치된 패키지를 우선하며, 없는 패키지만 동봉 파일에서 불러옵니다. 시스템 패키지를 설치하거나 업그레이드하지 않습니다.
- Python의 site-packages를 끈 환경에서 두 파서 로딩과 합성 HTML의 TXT 저장을 검증했습니다.
- 동봉 파일 출처·버전·해시·라이선스는 `vendor/README.md`에 있습니다.

### 0.1.2 변경 사항

- `soupsieve`가 없어 실행 준비에 실패하던 문제를 수정했습니다. 기본 CSS 선택자는 추가 설치 없이 내장 처리기로 동작합니다.
- 태그, ID, 클래스, 속성, 자손(공백), 직계 자식(`>`), 쉼표 선택자를 지원합니다. `:nth-child`, `:not` 등 고급 CSS는 SoupSieve가 설치된 환경에서 사용할 수 있습니다. 지원하지 않는 선택자는 설정 저장 시 안내합니다.
- FF의 다른 플러그인이나 Python 패키지를 자동 설치·변경하지 않습니다.

### 0.1.1 변경 사항

- 수집 모듈 import·초기화 실패 시에도 이름, 버전, 메뉴가 유지되고 오류 안내를 표시합니다.
- 패키지 누락 시 해당 FF Python과 설치 경로에 맞춘 설치 명령을 안내합니다.
- 정상 화면에 로딩 완료 상태를 표시하고 직접 사용하는 `soupsieve` 의존성을 명시합니다.
- `info.yaml`을 YAML과 JSON 양쪽에서 읽을 수 있는 형식으로 저장하여 FF 설치 시 정보 조회에도 대응합니다.

### 기존 ZIP 설치에서 Git 설치로 바꾸기

이미 ZIP으로 설치했다면 해당 폴더에는 Git 정보가 없어 업데이트가 되지 않습니다. FF를 중지하고 기존 `plugins/ff_gnuboard_downloader` **소스 폴더만** `plugins` 밖의 백업 위치로 옮긴 뒤 FF를 시작하여 위 주소로 설치하세요. `db` 폴더와 다운로드·정리 폴더는 옮기거나 삭제하지 않습니다.

### 수동 설치 참고

ZIP을 푼 `ff_gnuboard_downloader` 폴더를 FF 데이터 폴더 안 `plugins`에 넣고 FF를 재시작할 수도 있습니다. 자동 업데이트를 사용하려면 위 Git 설치 방식을 사용하세요.

FF 데이터 경로가 `/data`인 경우 파일 위치는 다음과 같아야 합니다.

```text
/data/plugins/ff_gnuboard_downloader/setup.py
/data/plugins/ff_gnuboard_downloader/info.yaml
```

`ff_gnuboard_downloader/ff_gnuboard_downloader/setup.py`처럼 폴더가 두 겹이면 로딩되지 않습니다. Synology File Station에서는 FF 컨테이너의 `/data`에 연결된 NAS 폴더를 찾아 그 안의 `plugins`에 복사하세요. 기존에 설치한 `munpia_free`와 나란히 두면 됩니다. 실제 데이터 경로가 `/data`와 다르면 그 경로를 사용합니다.

FF 컨테이너의 `requests`를 사용합니다. HTML 파서 `beautifulsoup4`와 `soupsieve`는 v0.1.3부터 함께 제공하므로 별도 설치할 필요가 없습니다. 직접 의존성을 관리하려는 경우에만 아래 명령을 사용하세요.

```bash
python3 -m pip install -r /data/plugins/ff_gnuboard_downloader/requirements.txt
```

플러그인은 시작할 때 pip 설치를 자동 실행하지 않습니다. 패키지를 설치한 뒤 FF를 재시작하세요. FF의 `plugin_loading_list`/`plugin_except_list` 또는 별도 개발 경로를 설정한 환경에서는 이 플러그인이 제외되지 않아야 합니다.

저장소 최상위에 `setup.py`, `info.yaml`, `core.py` 등이 있어야 합니다. 저장소 안에 `ff_gnuboard_downloader` 폴더를 한 겹 더 넣지 않습니다.

## 처음 실행

1. **설정 / 스케줄**에 `bo_table`이 들어 있는 게시판 목록 주소를 입력합니다. 제공한 목록 주소를 그대로 붙여넣어도 됩니다. `page`, `wr_id`는 자동 분리합니다.
2. 다운로드 폴더와 정리 결과 폴더를 지정합니다. NAS 경로가 아닌 **컨테이너에서 보이는 절대 경로**를 사용하세요. 예: `/books/inbox`, `/books/sorted`.
3. 설정을 저장합니다. 자동 실행 기능은 기본적으로 꺼져 있습니다.
4. **다운로더 → 시작 / 테스트 페이지 → 목록 분석**으로 제목·게시글 번호·마지막 페이지를 확인합니다.
5. **한 페이지 받기**를 실행하고 실제 TXT 파일을 확인합니다.
6. 한 페이지가 오류 없이 저장되면 **지정 범위 받기**, **시작 페이지부터 끝까지**를 사용할 수 있습니다.
7. **정리 → 파일 분석 / 미리보기**로 제목 묶음을 확인하고 복사합니다.
8. 필요한 경우 새 글 예약 확인, 다운로드 후 자동 정리, 별도 자동 정리를 켭니다.

| 다운로더 | 목록 분석, 한 페이지, 페이지 범위, 마지막 페이지까지 순차 수집, 새 글 확인, 일시정지·이어받기·중지 |
| 정리 | 제목 묶음 미리보기, 편수 표시, 선택 복사, 기준 충족 전체 복사 |

| 이력 / 오류 | 다운로드 성공·실패, 저장 경로, 오류 사유, 다운로드·정리 작업 이력과 상세 |

### 다운로드

- 파일 이름은 `게시글 제목.txt`입니다. 첫 줄에 제목, 빈 줄 뒤에 본문을 UTF-8로 저장합니다.
- 모든 새 TXT는 지정한 다운로드 폴더 바로 아래에 모읍니다.
- 게시판 주소와 `wr_id`를 내부 이력 키로 사용합니다. 화면에 표시되는 목록 순번은 식별자로 사용하지 않습니다.
- 정상 파일은 SHA-256 해시로 확인하여 다시 받지 않습니다. 이력이 있어도 파일이 없거나 달라졌으면 다시 받습니다.
- 파일명에 사용할 수 없는 문자, 지나치게 긴 제목은 안전하게 보정합니다. 같은 이름의 다른 내용은 `제목 [글-게시글번호-구분값].txt`로 별도 보존합니다. 기존 파일을 덮어쓰지 않습니다.
- 파일명 보정이 필요한 경우에도 정리할 때는 다운로드 DB의 원래 제목을 우선 사용합니다.
- 목록의 공지 표식이 있는 글은 제외합니다. 같은 목록 안의 중복 링크도 제외합니다.
- 수집 중 일부 글이 404 또는 빈 본문이면 이력에 실패를 기록하고 다음 글로 진행합니다. 해당 페이지를 다시 받으면 정상 파일을 건너뛰고 실패한 글을 재시도합니다.
- 로그인·차단·선택자 오류나 반복 페이지를 감지하면 전체 작업을 멈춥니다. 오류를 해결한 뒤 이어받을 수 있습니다.
- 새 글을 찾는 기능이며, 이미 저장된 게시글의 수정 내용을 자동으로 비교·갱신하지는 않습니다.

### 일시정지 / 이어받기 / 중지

- **일시정지**: 현재 페이지를 기록하고 멈춥니다. 완료된 TXT는 유지합니다.
- **이어받기**: 마지막 작업 페이지를 다시 확인합니다. 해당 페이지에서 이미 저장한 글은 건너뜁니다. FF 재시작 후에도 이력·작업 위치가 남습니다.
- **중지**: 이어받기 기록을 지우고 종료합니다. TXT와 다운로드 이력은 유지합니다.
- 이어받을 작업이 있으면 새 수동 작업을 시작하지 않습니다. 새 범위를 받으려면 중지 후 새 작업을 시작합니다.
- 주소·저장 경로·선택자를 바꾸면 이전 설정의 작업을 이어받지 않습니다. 새 설정에서 다시 한 페이지를 테스트하세요.
- 진행 중인 HTTP 요청은 응답 제한 시간까지 기다릴 수 있습니다. 읽기 제한은 응답 전체 시간이 아니라 응답 데이터가 오지 않는 시간 기준입니다.

### 새 글 스케줄

기본값은 **60분 간격, 1~2페이지 확인, 꺼짐**입니다. 첫 페이지부터 몇 페이지를 볼지 1~100페이지 범위로 지정할 수 있습니다. 설정 저장은 다운로드를 바로 시작하지 않으며, 켠 뒤 지정한 간격이 지나면 첫 실행을 합니다. FF 재시작 시에도 해당 간격 뒤에 다시 시작합니다.

확인 사이에 새 글이 확인 범위보다 많이 올라오면 일부를 놓칠 수 있습니다. 게시판의 갱신 속도에 맞춰 간격을 줄이거나 확인 페이지 수를 늘리세요. 예약 실행 사이에 사라진 글이나 지나간 모든 페이지를 자동 보충하는 방식은 아닙니다.

수동 수집이 실행 중이거나 일시정지되어 있으면 예약 실행을 건너뜁니다. 예약 확인 자체가 네트워크 오류로 실패한 경우는 다음 예약에서 첫 페이지부터 다시 확인합니다. 사용자가 일시정지한 작업은 자동 재개하지 않습니다.

### 정리

| 원래 제목 | 묶이는 제목 |
|---|---|
| 별빛 여행 - 1편 / 별빛 여행 2화 / 별빛 여행 (3) | 별빛 여행 |
| 산책 (상) / 산책 - 중 / 산책 하편 | 산책 |
| 기록 001 / 기록 002 | 기록 — 끝 숫자 인식 사용 시 |
| 제1차 탐험 1화 / 제1차 탐험 2화 | 제1차 탐험 |

- 기본 기준은 **3편 이상**이며 변경할 수 있습니다.
- 같은 회차인 `1화`, `01편`은 한 편으로 셉니다. 숫자·상중하 표기가 없는 파일은 한 제목 안에서 한 편으로 계산합니다.
- 회차 표기가 제목 끝에 있을 때 제거합니다. 제목 중간의 숫자는 유지합니다.
- 끝 숫자 인식은 기본적으로 켜져 있습니다. `프로젝트 2026` 같은 본제목의 끝 숫자와 회차는 완벽하게 구별할 수 없습니다. 미리보기로 확인하고 필요하면 옵션을 끄거나 회차를 뺀 묶음 제목을 제외 목록에 넣으세요.
- `1-1`, 로마 숫자, 본제목과 붙어 있는 `상중하`, 특이한 시즌·외전 표기는 별도 규칙을 추가해야 할 수 있습니다.
- 다른 작품이지만 제목이 같으면 자동 구분할 수 없습니다. 현재 정리 기준은 제목입니다.
- 정리 폴더는 `정리 결과 폴더/제목/기존 파일명.txt`입니다. 원본 파일은 유지합니다.
- 동일 내용의 복사본은 건너뜁니다. 같은 이름에 다른 내용이 있으면 `[다른내용-해시]`를 붙여 두 파일을 보존합니다.
- 원본 폴더 바로 아래 TXT만 검사합니다. 숨김 파일, 심볼릭 링크, 하위 폴더는 읽지 않습니다. 결과 폴더가 원본 하위에 있어도 재귀적으로 다시 수집하지 않습니다.
- 다운로드가 끝날 때 자동 복사할 수도 있고, 별도 간격으로 폴더를 검사할 수도 있습니다. 둘 다 꺼둔 상태에서 수동으로만 사용할 수도 있습니다.

## HTML 선택자

기본 설정은 사용자가 제공한 HTML 구조와 그누보드 기본 스킨을 처리합니다.

| 용도 | 기본 선택자 |
|---|---|
| 목록 링크 | `.list-body .item-subject, #bo_list .td_subject a` |
| 상세 제목 | `h1[itemprop="headline"], #bo_v_title .bo_v_tit` |
| 상세 본문 | `.view-content[itemprop="description"], #bo_v_con` |
| 페이지 이동 | `.pagination a[href], .pg_wrap a[href], .list-page a[href]` |

페이지 번호 `page`와 게시글 번호 `wr_id`를 사용하는 구조입니다. 페이지 이동의 마지막 화살표 링크에서 마지막 번호를 읽습니다. 마지막 링크가 없는 스킨에서는 보이는 다음 페이지 묶음을 따라가며 종료를 판단합니다. 페이지 링크 자체가 없으면 확인 가능한 현재 페이지까지만 수집합니다. URL 구조가 다른 게시판이나 자바스크립트로만 본문을 생성하는 사이트에는 추가 구현이 필요합니다.

상세 본문의 문단과 줄바꿈을 유지하고 script/style·숨김 요소를 제거합니다. 이미지·동영상·첨부파일·댓글은 저장하지 않습니다. 본문 영역 안의 광고 문구처럼 일반 텍스트와 구분되지 않는 요소는 사이트에 맞게 선택자를 좁혀야 합니다.

## 쿠키

로그인이 필요한 게시판은 설정의 로그인 쿠키에 브라우저의 **Cookie 요청 헤더 값**을 입력할 수 있습니다. 쿠키 JSON 내보내기 형식은 지원하지 않습니다. 빈칸으로 저장하면 기존 값을 유지하고, 삭제 체크 후 저장하면 지웁니다.

쿠키는 FF 데이터 폴더의 `db/ff_gnuboard_cookie.json`에 권한 0600으로 저장되며 암호화 저장은 아닙니다. 저장 당시 게시판과 일치할 때만 적용하고 다른 호스트로는 전송하지 않습니다. 쿠키 값은 화면 응답과 다운로드 이력에 포함하지 않습니다. 로그인 자동화·인증 우회·캡차 해제는 포함하지 않습니다.

## 데이터와 업데이트

- FF 설정: `{FF 데이터 경로}/db/ff_gnuboard_downloader.db`
- 다운로드 이력·작업 위치: `db/ff_gnuboard_download.db`
- 정리 미리보기·실행 이력: `db/ff_gnuboard_organize.db`
- 인증정보: `db/ff_gnuboard_cookie.json`

FF 데이터 폴더를 보존해야 이력과 이어받기가 유지됩니다. TXT 자체는 별도 지정 경로에 저장합니다. DB를 삭제하면 기존 파일의 게시글 ID를 알 수 없어 다시 요청할 수 있습니다. 다운로드 폴더를 바꾸면 새 경로에서 다시 저장합니다.

한 FF 인스턴스의 다운로드·정리는 공통 파일 잠금으로 동시 실행을 막습니다. 잠금·원자적 파일 확정에 Linux `fcntl`, 하드링크를 사용하므로 이를 지원하지 않는 파일시스템에서는 명시적인 오류가 발생할 수 있습니다. 일반적인 로컬 Btrfs/ext4에 볼륨을 연결하는 구성을 기준으로 합니다.

## 검증 범위

실제 대상 사이트에는 접속하지 않았으며 사이트 본문을 수집·분석하지 않았습니다. 제공된 DOM 구조를 중립적인 합성 제목·본문으로 재현해 시험했습니다.

자동화 시험 57개가 통과했습니다. 별도 로컬 모의 서버와 Chromium에서 설정 저장, 목록 분석, 한 페이지·끝까지 수집, 정리 미리보기·복사, 이력, 모바일 화면의 버튼 동작을 확인했습니다.

자동화 시험은 HTML 추출·페이지 이동, 중복 방지, 파일 무결성·충돌 보존, 일시정지·재시작·이어받기, HTTP 제한·재시도, 제목 묶기·편수·복사, 경로 보호, FF 설정·예약·CSRF·화면 렌더링을 확인합니다.

```bash
# ff_gnuboard_downloader 폴더의 상위 경로에서 실행
python3 -m unittest discover -s ff_gnuboard_downloader/tests -v
```

시험에는 `Flask`도 필요합니다. 실제 FF 컨테이너 설치 및 대상 사이트 로그인 세션으로의 다운로드는 아직 검증하지 않았습니다. 실제 시험에서 실패하면 이력 / 오류의 사유 또는 FF 로딩 로그를 기준으로 보완해야 합니다.

FF 연동 방식은 기존 문피아 플러그인과 FlaskFarm 공개 소스의 `create_plugin_instance`, `PluginModuleBase`, `Job`, 명령 라우트를 대조했습니다.
